# Major 瑞士轮模拟与游戏内 Pick'Em 作业

编写日期：2026-11-18。目标：**给定一张按种子排好的 16 队名单，算出每队 3-0 / 3-1 / 3-2 / 0-3
的概率，并给出使「答对 ≥ K 个」概率最大的 10 个竞猜格。**

代码：`scripts/major_sim.py`（模拟 + 优化）、`scripts/test/test_major.py`（含全 BO3 模式自检）。

全 BO3 模式：单阶段运行时加 `--all-bo3`，使当前阶段全部 33 场使用 BO3 胜率，例如：

```powershell
python scripts/major_sim.py --stage data/major/singapore2026/stage3.txt --all-bo3
```

整届 `--major S1 S2 S3` 运行时加 `--all-bo3`，仅 Stage 3 改为全 BO3；Stage 1/2 保持原混合赛制。不加参数时保持默认的 20 场 BO1 + 13 场 BO3。输出报告和 JSON 会记录实际使用的赛制。
种子表：`data/major/singapore2026/stage1.txt`（已填好新加坡 2026 真实名单）。
输出：`reports/major/<种子表名>/`。

## 1. 规则：V社瑞士轮

来源：Valve《CS Major Supplemental Rulebook》
（<https://github.com/ValveSoftware/counter-strike_rules_and_regs/blob/main/major-supplemental-rulebook.md>）。
32 队版本自 2025 年 1 月启用，结构为 **Stage 1 / 2 / 3 三个 16 队瑞士轮 + 8 队单败季后赛**。

### 1.1 基本结构

| 项 | 规则 |
|---|---|
| 人数 | 每阶段 16 队；三胜晋级、三负淘汰；共五轮 |
| 配对 | 同战绩对同战绩；阶段内不重赛（if possible） |
| 第 1 轮 | 固定 **1v9 2v10 3v11 4v12 5v13 6v14 7v15 8v16** |
| 第 2、3 轮 | 组内按种子排序后，"最高种子 vs **最低**种子中尚未交手者" |
| 第 4、5 轮 | 组内恰好 6 队 → 按规则书 **15 行优先级表**取第一条不产生重赛的行 |
| 阶段内种子 | （当前战绩，Difficulty，本阶段初始种子）三档依次比较 |
| Difficulty（Buchholz）| 已交手对手的（胜 − 负）之和；同战绩比它 |
| 阶段 2/3 种子 | 直邀 8 队 = 1-8 号（赛前全球 VRS 序）；上一阶段晋级 8 队 = 9-16 号（上一阶段最终种子序） |
| 季后赛 | Stage 3 前 8 名，1v8 4v5 / 2v7 3v6 单败。规则书规定全部 BO3 |

规则书第 4/5 轮的优先级表（组内 6 队，位置 1-6）：

```text
1v6 2v5 3v4 | 1v6 2v4 3v5 | 1v5 2v6 3v4 | 1v5 2v4 3v6 | 1v4 2v6 3v5
1v4 2v5 3v6 | 1v6 2v3 4v5 | 1v5 2v3 4v6 | 1v3 2v6 4v5 | 1v3 2v5 4v6
1v4 2v3 5v6 | 1v3 2v4 5v6 | 1v2 3v6 4v5 | 1v2 3v5 4v6 | 1v2 3v4 5v6
```

### 1.2 哪些场是 BO1、哪些是 BO3（关键）

规则书原文：**"All elimination and advancement matches are to be best of three.
All other matches are to be best of one."**

推论（本项目的判据）：**任一方已 2 胜（赢下即晋级）或已 2 负（输掉即淘汰）→ BO3，其余 BO1。**
16 队五轮下来恒定 **20 场 BO1 + 13 场 BO3**：

| 轮次 | 对阵池 | 场数 | 赛制 | 说明 |
|---|---|---:|---|---|
| 第 1 轮 | 0-0 | 8 | BO1 | 固定 1v9…8v16 |
| 第 2 轮 | 1-0 / 0-1 | 4 + 4 | BO1 | 组内最高 vs 最低未交手 |
| 第 3 轮 | **2-0** | 2 | **BO3** | 胜者 3-0 晋级 |
|  | 1-1 | 4 | BO1 | |
|  | **0-2** | 2 | **BO3** | 败者 0-3 淘汰 |
| 第 4 轮 | **2-1** | 3 | **BO3** | 胜者 3-1 晋级 |
|  | **1-2** | 3 | **BO3** | 败者 1-3 淘汰 |
| 第 5 轮 | **2-2** | 3 | **BO3** | 胜者晋级、败者淘汰 |
| 合计 | | 33 | **20 BO1 + 13 BO3** | |

这与赛事日程一致：每个阶段首日全是 BO1、次日混编（第 3 轮）、第三四日全是 BO3。
参考 [dust2.dk 的赛制说明](https://www.dust2.dk/nyheder/61997/saadan-foregaar-majorens-stadier)：
"Alle avancement- og elimineringskampe spilles som bedst-af-tre, mens resten af kampene er bedst-af-en …
tredje og fjerdedagen i hvert stadie udelukkende er Bo3."

**本项目对 BO1 与 BO3 各用各的胜率**：同一套逐图 `p` 走不同的 veto 协议（BO1 六 ban 留一张、
BO3 ban-ban-pick-pick-ban-ban）与不同的系列赛组合，不是把 BO1 胜率平方。模拟时按上面这张表
逐场选择用 `P_BO1` 还是 `P_BO3`，而不是用"统一胜率"。

### 1.3 由规则推出的结构事实

每阶段的结果分布**恒定**为 2 个 3-0、3 个 3-1、3 个 3-2、3 个 2-3、3 个 1-3、2 个 0-3。
这是 16 队五轮瑞士轮的组合必然，和实力无关。模拟器把这条当成运行时断言（`check_structure`），
配对逻辑一旦写错会立刻炸。

## 2. 游戏内 Pick'Em

Cologne 2026 起，Major Hub 里的竞猜按阶段进行（新加坡 2026 沿用同一套）：

| 项 | 规则 |
|---|---|
| 每阶段 10 格 | **2 个 3-0**、**6 个 3-1 或 3-2 晋级**、**2 个 0-3** |
| 通过线 | 答对 **6** 个（十中六）才算通过该阶段；纪念币升一级（青铜→白银→黄金→钻石，每级 300 tokens） |
| 槽位不能串用 | 把 3-0 队填进晋级格，该格**不得分**；把 3-1/3-2 队填进 3-0 格同样不得分 |
| 锁盘 | 每个阶段开打前锁 |
| 季后赛 | 换成 7 格：4 场 1/4 决赛 + 2 场半决赛 + 1 场决赛 |

参考：[CSGuess 的规则拆解](https://csguess.com/blog/cs2-major-pickem-guide-singapore-slot-trap-five-of-ten-math)、
[BUFF 的奥斯汀 Major 竞猜指南](https://buff.163.com/news/73736)（"选择两支 3-0 战队、两只 0-3 战队及六只
3-1、3-2 晋级战队""3-0 队伍贴在 3-1、3-2 组晋级框内不再得分"——**槽位结构两年未变**；
通过线以当期游戏内说明为准，本项目按 **十中六** 计算）。

> 通过线按 **十中六** 处理（`--threshold` 默认 6）。若某阶段改成别的线，
> 直接 `--threshold 5` 之类改一下即可，模型与模拟都不用动。

### 2.1 为什么 10 格的理论上限很低

因为结构恒定：3-0 只有 2 支队能答对（占 2/16）、0-3 只有 2 支（2/16）、3-1/3-2 共 6 支（6/16）。
所以即使完美按边际排序选最强的 2 支、次强 6 支、最弱 2 支，单格命中率也只有 20%~50%。
10 格的期望答对数通常在 3.5~4.5 之间徘徊——**这就是"十中六"属于高难度线的原因**：
要过线，6 个晋级格里至少要中 4 个，同时 3-0 那对还得中一支。

## 3. 实现

### 3.1 两两胜率（复用现有模型，不重新发明）

直接用项目已验证的逐图胜率 + 规则 veto 引擎（见 [ALGORITHM.md](ALGORITHM.md)）：

```text
p_m = clip( sigmoid(w_h·Δlog(HLTV) + w_s·分档差 + w_m·Δ回合残差 − c·Δ回避), 0.15, 0.85 )
BO1 = 六 ban 枚举；BO3 = ban-ban-pick-pick-ban-ban 枚举
```

要点：

- **一次装载、反复使用**。`series_probability.predict_pair` 每次调用都会重读 CSV 并重拟合 4 个参数，
  16 队两两要 120 次；`Pairwise` 把装载/拟合提出循环，只算 `map_probs` + veto 枚举。
- **方向严格互补**：`p(b,a) = 1 − p(a,b)`，所以只算上半三角。已实测 `sum = 1.000000`。
- **磁盘缓存**：`reports/major/_pairwise/pairwise_<指纹>.json`，指纹 = 数据哈希 + BP 配置哈希 +
  (as_of, engine, rail)。第二次跑同一批队伍是秒级。

### 3.2 瑞士轮模拟

每支队伍一个 `(w, l, 交手位掩码)`。逐轮：

1. 按 `(w, l)` 分组；
2. 组内按 `(−Difficulty, 初始种子)` 排序（Difficulty 用本轮开打前的战绩现算）；
3. 按 §1.1 的规则配对；
4. 逐场按 §1.2 的判据选 BO1 / BO3 概率，抽一个胜者。

两个实现细节值得单独说：

- **第 2/3 轮的"if possible"**：规则给的贪心（最高种子 vs 最低未交手者）在少数签表下会撞重赛，
  而换一种配对其实可以完全避开。代码先走贪心，**只有在出现重赛时**才枚举该组的全部完美匹配
  （8 队 = 105 种，优先级仍按"高种子先配最低"），取第一条零重赛的。这既忠实规则，又不会慢。
  跑 20 万次实测重赛数 = 0。
- **第 4/5 轮**就是 15 行优先级表逐行试；全部行都重赛时退化为"重赛最少"的行，并计数
  （`fallback`，实测 0）。

### 3.3 Pick'Em 优化

**目标函数不是"期望答对数最大"。** 10 格之间强相关（正好 2 支队 3-0、正好 2 支 0-3、正好 6 支
3-1/3-2），所以"最大化 10 个边际之和"和"最大化通过概率"是两个不同的最优点。
本脚本直接在**模拟出的联合分布**上最大化 `P(答对 ≥ K)`：

- 每个模拟样本给出 16 队各自的最终战绩（6 类），于是某套 10 格在样本 `s` 上的答对数 =
  该样本下命中的格数，可完全向量化；
- 起点：先解"最大化期望答对数"的指派问题（16 队 × 24 列的匈牙利算法，等价于常见的 ILP 写法）；
- 再用**交换邻域局部搜索 + 随机重启**改进 `P(≥K)`（交换两格的标签，增量更新答对数向量，
  不做全量重算）；
- 最后在全部模拟样本上复核。

对照基准：`只最大化期望答对数`、`按种子硬填`、`随机合法作业`（给出分布分位数）。
随机基准的存在是为了说明推荐解到底值多少——如果它只比"随便填"高一点点，那就没必要纠结。

### 3.4 整届串联（`--major`）

`--major S1 S2 S3`：Stage 1 模拟 → 取每样本前 8 名作为 Stage 2 的 9-16 号种子 → Stage 2 →
Stage 3 → 按 Stage 3 最终种子序排 1-8 号打单败季后赛（全部 BO3）。
输出每队「进 Stage 2 / 进 Stage 3 / 进季后赛 / 四强 / 决赛 / 夺冠」的概率。

注意：Stage 2/3 的 9-16 号种子在赛前是未知的，所以整届模式**只给 Stage 1 的作业**；
Stage 2/3 的作业要等上一阶段打完、把实际 16 队写进种子表再跑单阶段模式。

## 4. 输入：种子表

`data/major/singapore2026/stage1.txt`（`--init` 可重新生成）：

```text
# '#' 开头是注释，空行忽略；也可写 "1. MOUZ" 这种带编号的形式
Ninjas in Pyjamas
PARIVISION
HEROIC
...
```

规则就一条：**第 1 行 = 1 号种子 = 全球 VRS 最高的那支**，往下依次排到第 16 行。
队名必须是项目数据里有的（`data/team_maps/*.csv` 出现过），写错会直接报错并指出是哪一支。

Stage 2 / Stage 3 的种子表可以只写 8 行（8 支直邀），也可以用 `--major` 让它按模拟结果补；
要出这两个阶段的作业，必须写满 16 行。

## 5. 用法

```powershell
# 生成 / 重置种子表模板（已填好新加坡 2026 真实名单）
python scripts/major_sim.py --init

# 单阶段：给作业
python scripts/major_sim.py --stage data/major/singapore2026/stage1.txt

# 更稳的估计 + 三个通过线一起给
python scripts/major_sim.py --stage data/major/singapore2026/stage1.txt --sims 400000

# 换胜率引擎做敏感性检查
python scripts/major_sim.py --stage data/major/singapore2026/stage1.txt --engine points

# 整届：世界赛全程 + 夺冠概率
python scripts/major_sim.py --major data/major/singapore2026/stage1.txt `
    data/major/singapore2026/stage2.txt data/major/singapore2026/stage3.txt

# 自检
python scripts/test/test_major.py
```

| 参数 | 说明 |
|---|---|
| `--stage 文件` | 单阶段种子表（16 行） |
| `--major S1 S2 S3` | 整届三阶段串联 |
| `--sims N` | 蒙特卡洛次数，默认 120000（每阶段） |
| `--threshold 6` | 通过线（答对几个算过），默认 6 |
| `--as-of 日期` | 预测日期，默认 2026-11-24（Major 开赛日），须晚于数据截止日 |
| `--engine tier\|points` | 逐图胜率的第二列引擎 |
| `--rail 0.15` | 对称概率护栏 |
| `--out 目录` | 输出目录 |

输出目录内容：`report.md`（含规则、每队概率、每格候选、推荐作业、稀有度对照、胜率矩阵）、
`prediction.json`、`outcomes.csv`。

## 6. 验证

`python scripts/test/test_major.py`（12 项，含全 BO3 胜率矩阵与场数检查，不需要重训模型）：

| 测试 | 断言 |
|---|---|
| 第 1 轮配对 | 必须是 1v9…8v16 |
| 优先级表 | 15 行、每行是 6 个位置的一个完美匹配、互不相同、首行是 1v6 |
| 赛制与结构 | 恒定 20 场 BO1 + 13 场 BO3；结果分布 2/3/3/3/3/2；重赛数 0 |
| BO3 只用在晋级/淘汰战 | 把 BO1 全设 0.5、BO3 设随机，结果必须改变 |
| 强者恒强 | `i<j ⇒ i 必胜` 的矩阵下，3-0 必是 1、2 号种子，0-3 必是 15、16 号 |
| 最终种子排序 | 先战绩、再 Difficulty、再初始种子 |
| 格子配额 | 2 / 6 / 2，且 10 格是 10 支不同的队 |
| 答对数分布 | 概率和为 1、`≥5 ≥ ≥6 ≥ ≥7`、期望与分布一致 |
| 优化器 | 迭代局部搜索解不低于"只最大化期望"的解 |
| 种子表解析 | 注释、空行、`1.` / `1、` / `1)` 前缀，且不误伤 `9z`、`1win` |

**联合分布与偏差的三项实测检查**（每次跑都会打印在报告第 6 节）：

| 检查 | 结果 | 含义 |
|---|---|---|
| 半样本交叉验证 | 样本内 13.7% → 样本外 14.1%；两半各自求解**选出同一套作业** | 没有过拟合到样本 |
| 选择偏差对照 | 600 个随机作业里挑"样本内最好"，样本外 −0.1pp | 该目标下"挑最好"几乎不虚高 |
| 错误地按独立格计算 | Poisson-binomial 给 15.2%，真实 13.7% | 忽略联合会**高估 1.5pp**（槽位互斥 + 3-0 队填进晋级格不得分） |

第一项说明优化器没有在样本上"编"出通过率；第三项说明为什么必须用联合分布——
10 格之间是**负相关**的：你把某队填在 3-0，它若打成 3-1，你既丢了这个 3-0 格，
也拿不到它本该在晋级格里的那一分。

运行时自检（每次跑都会做）：结构分布、20+13 场、重赛数、方向互补（`p(a,b)+p(b,a)=1`）。

### 7.2 作业（200,000 次模拟，通过线 = 答对 6 个）

| 格 | 队伍（括号内 = 该格命中率） |
|---|---|
| 3-0 | Ninjas in Pyjamas（25%）、PARIVISION（24%） |
| 晋级 3-1/3-2 | HEROIC（49%）、FaZe（50%）、Liquid（51%）、Eternal Fire（50%）、100 Thieves（48%）、9z（36%） |
| 0-3 | Chinggis Warriors（36%）、Lynn Vision（26%） |

**通过概率 13.7%**，答对数分布：6 个 9.7% + 7 个 3.1% + 8 个 0.8% + 9 个 0.1%。

对照（同一通过线）：

| 方案 | ≥6 概率 | 期望答对数 |
|---|---:|---:|
| **优化解 = 按种子硬填** | **13.7%** | 3.95 |
| 只最大化期望答对数 | 12.8% | 3.97 |
| 随机合法作业（中位 / 95% 分位 / 1000 个里最好） | 1.1% / 4.4% / 9.2% | — |

**这一档的结论很干脆**：在十中六的线上，**优化解就是"按种子硬填"**——把 1-2 号种子放 3-0、
把 3-8 号放进晋级格、把最弱两支放 0-3，没有任何更好的操作空间。
原因是 Stage 1 前 7 支队实力几乎相同（§8.1），任何"腾挪"都是把一个 ~20% 的 3-0 机会
换成另一个 ~20%，净收益在噪声里。

引擎敏感性：换成 `--engine points` 后通过概率 **14.3%**，推荐名单相同。

## 8. 已知限制

1. **同档即 50%**：`tier` 引擎故意放弃档内强度差异。新加坡 Stage 1 的前 7 支队 VRS 只差 130 分、
   基本落在 1-2 个档内，所以模拟出的赛场非常"平"——7 支队每个 3-0 概率都在 19%~25%。
   后果是：在十中六这条线上，**优化解与"按种子硬填"完全重合（都是 13.7%）**。
   这不是 bug，是模型的取值方式：
   若你认为某两支同档队伍强弱分明，它不会反映（除非回合残差不同）。
2. **护栏压缩尾部**：`p ∈ [0.15, 0.85]` 让极端碾压局最多只到 85%，头部队的 3-0 概率因此被低估、
   尾部爆冷被高估。想看放开尾部后的差别，用 `--rail 0.05` 对比。
3. **BO5 偏高**（见 ALGORITHM §9）；季后赛按规则书用 BO3，若赛事把总决赛改 BO5，
   夺冠概率应向强队再偏一点。
4. **阶段间独立**：模拟不把上一阶段的状态/手感带进下一阶段，这与"每阶段重新按种子配对阵"一致，
   但真实比赛里休息与气势是会传递的。
5. **没有真实 veto 数据**：BP 层仍是情景假设（ALGORITHM §12.5），BO1/BO3 的差别主要来自
   系列赛组合的数学，而不是被验证过的 BP 行为。

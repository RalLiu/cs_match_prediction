# 设计总览

日期：2026-11-18。当前只维护**分档强度模型 + BP 情景预测**这一条链路。
算法细节、公式、参数、验证数字见 [ALGORITHM.md](ALGORITHM.md)；历史方案见 `archive/v5/`。

## 1. 系统做什么

输入端只有两样东西：**70 份人工整理的比赛 CSV**（2026-06-23 至 11-17，4105 张地图）和
**两张当期积分快照**（HLTV 248 队、Valve 345 队）。不做实时抓取。

输出：任意两队的 **BO1 / BO3 / BO5 胜率**，并且是**地图感知**的——先算七张地图各自的胜率，
再用 BP 规则枚举出所有可能的出图集合，按集合把系列赛概率积起来。

```text
比赛 CSV + 积分快照
  → 规范化、镜像合并、按日期滚动构造赛前状态
  → 逐图胜率（3 特征强度模型 + 对称护栏）
  → BP/veto 枚举（首ban规则 + 动作 softmax）
  → 系列赛 best-of-k + 全部地图集合范围
  → 点估计、区间、比分分布、Top 出图序列
```

## 2. 四条设计原则

**① 只保留数据能支撑的东西。**
10 个特征、4 个模型、融合与温度校准，最终只值 OOF LogLoss 从 0.6162 到 0.6248 的差别。
现在只留三个特征：HLTV 差、积分档差、回合净胜残差。动态地图、被针对代理、缺分标记、
整体状态与趋势全部实测无效，已删除。逐项的 OOF 对照见 ALGORITHM 第 4 节。

**② 地图差异只允许来自一个来源。**
每队每图的回合净胜残差。这是唯一在 OOF 上有正贡献的地图信号。
历史上"回避项"曾把地图胜率拉开 ±20pp，实测无效，现在系数被压到 0.348 且限制在 [0,1]。

**③ 团队强弱用"档"而不是"分"。**
同一分差在顶区兑现率更低（顶区 +0.4 以上实测 0.647，低区 0.745）。
档宽随积分增长（80 + 6%×积分，共 13 档），**同档内视为同一水平**——
档内差异交给回合残差，系列赛结果交给 veto。这让顶区预测更稳（≥1700 子集 LogLoss 0.6779 vs 0.6832），
整体也略好（0.6162 vs 0.6167），准确率更高（67.11% vs 66.81%）。

**④ 宁可承认"不知道"，也不假装知道。**
首ban 规则原本用均匀 1/7 当先验、对任何样本量都给出确定答案，这会把噪声当信号。
现在先验改用近 90 天全局出图率（Anubis 9.4% vs Dust2 18.3%），并要求
"按全局率这张图本该出场至少 2 次"才采信；不满足时改为在剩余图上均分，
并在 `first_ban` 字段里写清证据。324 支队伍里只有 14% 达标。

## 3. 明确不宣称的东西

- **BP 动作概率没有训练过。** 七个权重与温度是手工设定，报告里一律标注"情景假设，非校准频率"。
  没有真实 veto 数据，也没有 BP 回测。
- **没有博弈规划。** 评分是逐步的，不做后向归纳，不声称是均衡策略。
- **BO5 点估计偏高。** 组合放大约 1.5 倍，叠加单图尾部偏乐观。所以每次输出都同时给集合范围，
  报告正文提示优先参考区间。
- **地图特化做不了。** 队伍×地图有效场次中位数 1.95，任何"某队某图特别强"的建模都是噪声。
- **积分快照回填历史** 是最主要的泄漏源，所有历史指标都应打折看。

## 4. 为什么不做学习（也不做数据扩张）

| 试过 | 结果 |
|---|---|
| 自建 Elo / BT / 回合差评分（265 参数） | 0.65~0.70，远差于积分快照 |
| rating × 地图交互 | 无增益 |
| 赛事层级代理 | 0.6166，零增益 |
| 积分 log / 幂 / 秩 / 分段变换（17 种） | 全部 ≤ 基线 |
| 概率整体缩放 / isotonic 校正 | λ\*=1.0；isotonic 更差 |
| 扩历史到 3~5 年 | 训练窗口实验显示 30 天 ≈ 全历史，久远数据无增量；且阵容/图池变化使其无效 |

结论：以现有信息集，0.616 附近就是上限。想真正提升需要**阵容/选手**与**真实 veto** 这两类数据，
而不是更复杂的模型。Liquipedia 可以补赛事层级、地图池与阵容变动（已验证可行，见 `tools/`），
但没有 veto，也没有选手评分。

## 3. 逐图胜率

三个特征 + 一个回避项 + 一个护栏。第二列有两种引擎，**默认 `tier`**。

```text
z_m = w_h · [log(1+HLTV_A) − log(1+HLTV_B)]
    + w_s · second(A, B)
    + w_m · [margin_A(m) − margin_B(m)]
    − c   · [avoidance_A(m) − avoidance_B(m)]

p_m = clip( sigmoid(z_m), 0.15, 0.85 )
```

`margin(m)` 是每队每图的**回合净胜残差**（30 天半衰期、`n/(n+8)` 收缩、先减去整体 Elo 预期）。
这是唯一有验证价值的地图差异来源，也是"同档对局之间为什么还有区别"的唯一来源。

### 3.1 引擎 A：`tier`（默认）

```text
档位 index(p) = 从 p 出发，每次加 (80 + 6% × 当前积分)，直到达到全榜最高分，累计步数
second = (index(Valve_A) − index(Valve_B)) / 5
```

- 档宽随积分增长：顶档约 195 分宽，低档约 128 分宽 → **同档内不加区分**。
- 当前 13 档。FURIA = 第 1 档、Spirit = 第 1 档、Falcons = 第 2 档、paiN = 第 5 档。
- 缺榜队伍用"全榜中位数对应的档位"。
- 依据：同一分差在顶区兑现率更低（顶区 +0.4 以上实测 0.647、低区 0.745）。
  OOF 上该引擎全面优于原始分差（见第 7 节）。

### 3.2 引擎 B：`points`（回退）

```text
second = (Valve_A − Valve_B) / 400
```

等价于把 Valve 积分当 Elo 用。用于对照与回溯旧结果。

### 3.3 三种引擎的拟合参数（全量 4105 行）

| 参数 | tier | points |
|---|---:|---:|
| `w_h`（HLTV） | +0.1573 | +0.0701 |
| `w_s`（第二列） | −1.8297 | +1.1734 |
| `w_m`（回合残差） | +2.1895 | +2.2985 |
| `c`（回避） | 0.348 | 0.377 |

（`tier` 的 `w_s` 为负是因为档位序号 0 = 最强。）

拟合细节：加权逻辑损失 + 权重 L2 = 0.02 + 回避向 1 的 L2 = 0.01；样本权重 `2^(−age/30) × 1/k`（k = 系列赛地图数）；
无截距，保证 `p(A,B) + p(B,A) = 1`。

### 3.4 对称护栏

`p_m ∈ [0.15, 0.85]`。依据：预测 >0.9 的 106 个样本实测只有 0.868；预测 <0.15 的 294 个样本实测 0.241；
全部 4105 行没有任何分桶超过 0.87。OOF 上护栏裁剪 1.3% 样本、**LogLoss 代价 0.0000**。

### 3.5 回避项

```text
avoidance = max(0, 1 − 近30天该图次数 / 3)
          × min(1, 近30天全部图数 / 20)
          × min(1, 距上次打该图后其他图数 / 10)
```

方向（"回避 → 更弱"）是结构性假设，不是从 ban 标签学到。系数由数据拟合并限制在 `[0, 1]`，
tier 引擎下为 0.348——远低于历史工件的 0.852，因为更大幅度会造出数据里不存在的极端值。

## 4. 为什么只有三个特征

全部在同一套前向折上实测（3 折合并 OOF）：

| 特征 / 做法 | OOF LogLoss | 结论 |
|---|---:|---|
| `hltv + second + margin` + 回避（现行） | **0.6162**（tier）/ 0.6167（points） | 保留 |
| 加 `dynamic_map`（每图实力残差） | +0.0057 | 删除 |
| 加 `counterpick_proxy`（疑似被针对） | +0.0070 | 删除 |
| 加 HLTV/Valve 缺榜标记 | +0.0065 | 删除 |
| 加 14/60 天整体状态与趋势 | +0.0088 | 删除 |
| 加 rating × 地图 交互 | +0.0089 | 无地图特化信号 |
| 加赛事层级交互（本地自估） | −0.0001 | 零增益 |
| 按地图等权训练（非系列赛等权） | +0.0023 | 删除 |
| 系列赛级直接建模（绕开逐图相乘） | 0.6420 vs 0.6362 | 保留"逐图相乘" |
| 自建 BT / 回合差评分 | 0.65~0.70 | 样本不足，不可用 |
| 分档 "每档独立强度"（自由拟合） | 0.6204~0.6297 | 过拟合，只用序数间隔 |

硬约束：队伍×地图单元格 1344 个，有效场次**中位数 1.95**、`P(n<5) = 79%` —— 地图特化学不出来。

## 5. BP / veto 层

### 5.1 profile（每队每图）

| 字段 | 含义 |
|---|---|
| `avoidance` | 第 3.5 节公式 |
| `usage` | 近 30 天该图出场 / 近 30 天全部出场 |
| `time_weighted_usage_probability` | 21 天半衰期指数加权出场占比 |
| `smoothed_recent_win_signal` | `2·((wins+4)/(n+8) − 0.5)` |
| `preference.share_trend` | 近 30 天占比 − 前 30 天占比 |

出场 ≠ 主动 pick（可能来自对手 pick 或决胜图）。

### 5.2 首ban规则（`step < 2`）

对双方各自的第一个 ban，从**原始七图池**取"加权出场占比相对全局出图率最低"的图：

```text
share(m)   = (21天半衰期加权出场次数 + κ·rate_m) / (加权总质量 + κ)     κ = 2.0
rate_m     = 该图近 90 天的全局出图率（Anubis 9.4% / Dust2 18.3% / …）
expected_m = 加权总质量 × rate_m       # 若正常打，这张图"本该出现"多少次
```

- **先验不是均匀 1/7**。用 1/7 会把"该图本来就少见"误判成"该队不打它"。
- **证据门槛**：若最低图的 `expected < 2.0`，判为证据不足 → **改为在剩余图上均分**，
  不假装知道它会 ban 哪张。
- 并列则均分；若最低图已被对手 ban，回到正常综合评分，**不会**自动 ban 第二低的图。
- 每次输出都在 `first_ban` 字段里记录：`decision`（`rule` / `insufficient_evidence` /
  `fallback_composite` / `rule_legacy`）、最低图、该图的加权出场、有效样本量、全局出图率、`expected`。

**为什么需要门槛**：324 支队伍的有效样本量（21 天半衰期加权质量）中位数只有 1.17，
72% 的队伍 < 5。若不做门槛，一支只打了 2 场的队伍也会被"确定地"判出一张首ban——
那是噪声。按 `expected ≥ 2` 筛，只有 **46 / 324（14%）** 的队伍证据足够。

**实测影响**（top-12 两两共 66 组 BO3，新旧规则对比）：平均 |Δ| = 0.28pp、最大 2.1pp、
8 组变化超过 1pp、0 组超过 3pp。也就是对覆盖充分的强队，改的是"依据是否可靠"而不是结论；
而对证据不足的队伍，旧规则给出虚假的确定性。对实力悬殊的对局几乎无影响——
因为七图胜率接近相同时，veto 本来就对系列赛结果无作用（见 6.4）。

### 5.3 正常动作评分（softmax 只在合法剩余图上）

```text
ban(m)  = 4.0·自身回避 + 2.0·对手 usage·(1−p_m) + 1.0·log((1−p_m)/p_m)
pick(m) = 3.0·自身 usage + 1.0·log(p_m/(1−p_m)) + 0.4·平滑近期胜率 + 1.0·图池趋势
P(m)    = softmax( score(m) / temperature )，temperature = 1.0
```

权重与温度为**手工设定**（`configs/bp_rules.json`），未经真实 Veto 标签训练、无回测。

### 5.4 枚举

| 赛制 | 动作序列 | 胜场目标 | 路径 |
|---|---|---|---:|
| BO1 | ban × 6 | 1 | ≤10080 |
| BO3 | ban, ban, pick, pick, ban, ban | 2 | ≤10080 |
| BO5 | ban, ban, pick, pick, pick, pick | 3 | ≤10080 |

先手未知（A 先 / B 先各 0.5），两情景完整枚举。理论上限 10080；因首ban通常确定，
真实对局多为 **240** 条。每条路径概率 = `0.5 × Π 各步动作概率`，断言 `Σ = 1`。

## 6. 系列赛数学

### 6.1 best-of-k

给定会打的地图集合与逐图 p，穷举 `2^n` 种胜负组合，累加"A 赢的图数 ≥ 目标"的组合概率。
地图条件独立 ⇒ 顺序无关，只需集合。

### 6.2 早停与比分分布

`predict_bp.series_details` 用递推实现早停，产出终局比分与各图实际开打概率（BO3 合计 2.5、BO5 合计 4.125）。

### 6.3 集合范围（对 veto 的诚实度量）

veto 未知时不假装知道会打哪几张图，而是枚举全部合法集合：

| 赛制 | 集合空间 | 数量 |
|---|---|---:|
| BO1 | 任意 1 张 | 7 |
| BO3 | 任意 3 张（2 pick + 1 剩余） | 35 |
| BO5 | 任意 5 张（4 pick + 1 剩余） | 21 |

报告 min / max。**区间宽度 = 地图与 veto 到底影响多少**，不依赖任何手设权重。

### 6.4 七图同值时 veto 无效

若 `p_1 = … = p_7 = p`，任意集合结果都等于二项式（BO1 `p`、BO3 `3p²(1−p)+p³`、BO5 `10p³(1−p)²+5p⁴(1−p)+p⁵`），
集合范围退化为单点，veto 与 BP 温度的影响**严格为 0**。这是假设的数学必然，不是缺陷。

## 9. BO5 为什么偏高

三个叠加因素，按贡献排序：

1. **组合放大**：单图 p=0.66 → BO3 73.2% → BO5 **78.0%**。灵敏度：单图 +0.01 → BO5 +0.015~0.018（约 1.5 倍）。
2. **单图尾部偏乐观**：预测 >0.9 的样本实测 0.868；>0.85 区间实测 0.806；Valve 差 ∈[0.9,1.2) 实测 0.723（模型 0.794）。
3. **规则 veto 偏向强队**：`pick` 含 `log(p/(1−p))`、`ban` 含 `log((1−p)/p)`，集合被推向强队有利组合
   （FURIA–Falcons：二项 76.0% → 规则点估计 78.1%）。

**当前处置**：三种赛制同时输出 `p_a`、`set_range`、`veto_free_binomial`，报告正文固定提示"BO5 点估计偏高，
优先参考集合范围"。

**已验证无效的降法**（都不要采用）：积分 log/幂/秩变换（11 种）、整体 logit 缩放（λ\*=1.0）、
对称 isotonic 校正（−0.006）、系列赛级收缩（交叉验证两个方向都变差）、"每档独立强度"。

## 12. 已知限制

1. **积分泄漏**：单一快照回填全部历史，历史期特征含未来信息。
2. **无阵容/无时刻**：同一天多图、换人、休息都无法区分。
3. **地图特化不可学**：队伍×地图有效场次中位数 1.95。
4. **出场 ≠ pick**：BP 层全部基于出场统计，没有真实 veto 记录。
5. **手工权重**：BP 的 7 个权重是情景假设，输出是"若双方按此偏好行动"的推演。
6. **同档即 50%**：tier 引擎故意放弃档内强度差异；若你认为某两队同档但强弱分明，
   本引擎不会反映这一点（除非它们的回合残差不同）。

## 13. 用法

```powershell
# 生产：任意两队三种赛制
python scripts/predict_bp.py FURIA Spirit --format all
python scripts/predict_bp.py "Natus Vincere" "The MongolZ" --format BO3
python scripts/predict_bp.py FURIA Falcons --engine points      # 回退到原始积分差
python scripts/predict_bp.py FURIA Falcons --out 临时目录        # 不写 reports/bp

# 不落盘的单次查询 / 条件预测
python scripts/series_probability.py FURIA Spirit
python scripts/series_probability.py FURIA Falcons --maps Ancient,Dust2,Mirage
python scripts/series_probability.py FURIA Spirit --json

# 验证
python scripts/evaluate.py     # 地图级 + 系列赛级 OOF 对照
python scripts/test/test_bp.py      # 枚举与概率正确性
```

输出：`reports/bp/队A__队B__日期/{prediction.json, report.md, BO*_all_paths.csv}`。
`prediction.json` 的 `provenance` 记录引擎、档位、强度权重、回避系数、护栏、地图行数、数据截止日、缺榜队伍、全部输入文件 SHA-256；
`first_ban` 记录双方首ban 的判定方式与证据（最低图、加权出场、有效样本量、全局出图率、本该出场次数）。

排查首ban 依据：

```powershell
python tools/inspect_profile.py FURIA Spirit   # 两队七图的出场/回避/首ban 依据
python tools/inspect_profile.py --survey      # 全 324 队的证据强度普查
```
